UNSAID Anonymous messaging API

The REST backend for an NGL-style anonymous messaging app — 60 endpoints across auth, user and message modules. The receiver can ask who sent a message; only if the sender accepts does a private two-person conversation open. Until then, the sender's ID never leaves the database.

60Endpoints
171End-to-end checks
15 minAccess-token life
30 daysAccount restore
  • Request-to-reveal identityThe receiver asks who sent a message; the sender accepts or rejects. Accepting opens a private conversation linked to the original message that only the two participants can read or write.
  • Brute-force lockout with RedisFive failed logins lock the account for 5 minutes using Redis counters that expire on their own. The API returns attempts left and a Retry-After countdown, and emails a security alert.
  • 2-step verification & hashed OTPsEmail 2-step at login. OTPs are stored as HMAC hashes bound to a purpose (verify, reset, restore, 2-step), with a 5-try limit, a 60-second resend cooldown and one-time atomic use.
  • Rotating refresh tokens15-minute access tokens and rotating 7-day refresh tokens tracked per device, with reuse detection, logout from one or all devices, and sessions revoked on password change.
  • Moderation & privacyBlock users — even anonymous senders, without revealing them — report messages, accept or refuse guest messages, publish a message with a public reply, and soft-delete with a 30-day restore.
  • Hardened, then provenRedis rate limiting, idempotency keys and versioned caching; Multer uploads checked by file signature; helmet, credentialed CORS, stable error codes. Fixed inherited bugs — a sender leak in the inbox, exposed password hashes, 41-day tokens — and verified it all with 171 end-to-end checks against real MongoDB and Redis.
